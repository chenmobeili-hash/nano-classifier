平均数只告诉你“总量怎么平分”，却不告诉数据是怎么分布的。比如两组各 5 个人，平均分都是 70：一组可能是 68、69、70、71、72，大家差不多；另一组可能是 0、0、70、100、100，有人极差有人极好。平均数一样，但体验完全不同。这就是为什么看数据还要看“分散程度”（比如最高最低差多少、多数值离平均数有多远），并且最好画个图看看形状。

Because a simulation isn't truly random—it's a recipe. A computer runs a fixed set of steps (a pseudo-random generator) that spits out numbers that behave like randomness, and our brains are pattern-detecting machines, so two things happen at once.

First, real randomness isn't evenly spread. If you flip a coin 100 times, you'll almost certainly see streaks like HHHH or TTTTT. People expect alternation, so when they see a run they think "that can't be random," but clumping is exactly what randomness looks like. Second, the algorithms we use have structure: they cycle, they use seeds, and if you plot successive pairs you can sometimes see grid lines. That's an artifact of the method, not of chance.

And there's a third, bigger reason: given enough output, some pattern is guaranteed to show up. It's like noticing that a friend's birthday falls on a Tuesday three years in a row—surprising in isolation, but unremarkable once you consider how many coincidences you're silently checking. Simulations make this visible because they're fast and cheap: generate a million numbers and weird-looking regularities will appear, not despite the randomness but because there's so much of it.

So when you see a pattern in simulated randomness, ask: does it survive a rerun with a different seed? If yes, it might be a real property of the system you're modeling. If no, it's just noise wearing a costume.
