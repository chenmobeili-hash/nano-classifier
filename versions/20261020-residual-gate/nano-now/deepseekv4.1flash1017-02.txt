3882。用容斥计数，记 P(a→b) 为从 a 到 b 的单调路径数（组合数）：
- 总路径 C(16,8)=12870；
- 经过 (2,2)：C(4,2)·C(12,6)=6×924=5544；
- 经过 (4,5)：C(9,4)·C(7,3)=126×35=4410；
- 经过 (6,3)：C(9,6)·C(7,5)=84×21=1764；
- 同时经过 (2,2) 与 (4,5)：6×C(5,2)×35=6×10×35=2100；
- 同时经过 (2,2) 与 (6,3)：6×C(5,4)×21=6×5×21=630；
- (4,5) 与 (6,3) 互不可达（一者需向左一者需向下），故交集为0。
结果 = 12870 − (5544+4410+1764) + (2100+630) = 3882。
可复核代码（未执行，仅列出）：
```python
from math import comb as C
def p(a,b): return C((b[0]-a[0])+(b[1]-a[1]), b[0]-a[0])
W=(8,8); B=[(2,2),(4,5),(6,3)]
ans=p((0,0),W)
for i,x in enumerate(B): ans-=p((0,0),x)*p(x,W)
for i in range(3):
    for j in range(i+1,3):
        x,y=B[i],B[j]
        if x[0]<=y[0] and x[1]<=y[1]: ans+=p((0,0),x)*p(x,y)*p(y,W)
print(ans)  # 3882
```

Randomness on a screen never really looks random — that's the trick. When a computer or a person "makes up" random results, it still has to follow steps, and steps have habits. So you'll see runs of heads, or the number 3 showing up three times out of five rolls, or a digit repeating too often. That's not the simulator breaking; that's just what actual random data does. Truly random data is lumpy and streaky, because every sequence is allowed. The only patterns that should worry you are patterns in the *rules* (same result every time, or a cycle that repeats on a schedule), not patterns in the *output*. Think of it like rain on a window: the drops are random, but you'll still see clusters and gaps. Seeing a cluster doesn't mean the rain is rigged.
