# UI复核功能

入口仍是项目根目录「最新版_粘贴答案测试.bat」，本次只更新残差门控版页面及本机服务，不更换模型、训练库或评分权重。

## 使用

1. 关闭旧测试服务窗口，重新启动脚本。粘贴完整24题，点击开始对照测试。
2. 评分区可点击「手动复核」，无需联网或Key；基于已有评分起草，逐题修改。
3. 要用AI：在页脚右侧小圆点「·」上，2.4秒内连点5次，打开服务设置。填兼容API地址、模型名、Key。可以填写`https://你的服务/v1`或完整`.../chat/completions`地址；本机模型可用`http://127.0.0.1:端口/v1`，免Key。
4. 点击「AI辅助复核」才会发送A01–A12题作答和固定评分依据；B题不发送。不会使用或消费其他已登录账户的额度。
5. 展开12题核对原文、最终结果对错、内容/过程比例、一致性上限、判定理由及逐字引文。AI不是独立人工判卷，引文来自原文也不代表推理正确。
6. 修改后先点「预览改分」。页面对照显示旧版、严格格式版、结果、格式与200分合计。
7. 勾选逐题确认，再点「确认并保存复核」。如A题摘要已有旧复核，必须另勾「替换旧复核」；否则不会覆盖。

Key仅存当前Python服务内存，不写浏览器存储或配置文件，不回显到页面和API响应。刷新网页可沿用本次设置；关闭服务后需重填。关闭设置框会清空未提交的Key输入；「清除设置及Key」清掉服务端本次配置。

连点入口只是减少界面干扰，不是认证机制。本机接口继续绑定127.0.0.1，校验Host、Origin与随机会话令牌。远程服务必须HTTPS；禁止自动跟随跳转携带Key。

## 评分口径

内容分沿用既有A题比例，填写0–1的小数；该比例是施加一致性封顶之前的分数。普通推导题为结论60%+方法40%，完整方法40%、半方法20%、无有效方法0%；A10为胜负20%+全部首步40%+方法40%；A05路径与权重各50%，A06最终值40%与序列60%；A07–A09内容80%+旧版局部格式20%。

一致性上限选1、0.9、0.8、0.6，分别表示无额外封顶、错误过程已更正、错误结论已更正、未撤回冲突；严格版自动映射为1、0.85、0.7、0.5，与内容失分取较低值，不重复叠扣。

最终结果分要求题目所需结果全部正确，忽略过程、格式和明确更正。A10胜负正确但首步有错不能算结果完整正确。格式由本机原规则计算，AI不新增B开放语义扣分。A07–A09严格内容仍沿用现有可提取正确输出的规则，边界情况应结合预览检查。

## 保存与回退

草稿保留在服务内存中1小时；改答卷、改服务设置、重启后旧草稿不能再保存。修改草稿未重新预览也不能保存。多人/多窗口同时写入或资料已变化时拒绝过期保存。

保存后更新`sample_reviews.json`、`result_reviews.json`及静态综合/结果榜单，并刷新当前服务的评分缓存。对库外答卷保存复核仅按A题摘要关联，不创建训练样本，也不推断身份。其他已打开的旧服务窗口请重启。

每次保存会在运行目录的`ai_review_history/UTC时间-随机号/`保留旧6个评分/榜单文件、完整原答卷和接受的12题复核。来源标记为「AI辅助复核，经用户逐题确认」或「用户手动复核」，不伪称独立人工复核。未完成的保存会回滚；下次启动如发现完整事务备份会恢复。正在保存的其他服务不会被自动覆盖。

## 接口与限制

使用Chat Completions兼容JSON接口，只传`model`、`messages`、`stream:false`，避免强制添加部分推理模型不支持的温度或输出格式参数。参考[官方接口文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。不同服务的兼容性和模型判断质量需要实际验证。

每次最多9万字符整卷、6万字符A题；请求180秒超时，无自动付费重试。只接受恰12题的有限数值、布尔结果、允许的上限和逐字原文引文；格式错误或缺题会拒绝整份草稿。系统规范和待评答卷分开提供，但仍需用户核对以防提示注入、错误推理和评分漂移。

验证使用本机模拟API，无真实付费调用。已覆盖隐藏入口、手动草稿、编辑/预览/确认、密钥不回显与不落盘、过期答卷、JSON约束、接口会话校验、备份回滚和事务恢复。识别网络及既有100份分数在发布时不变。
